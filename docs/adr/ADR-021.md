# ADR-021 会议室协议：七个常设会议室 + 六步结构化讨论（独立陈述 → 质询 → 回应 → 综合 → 决议 → 纪要）

- 状态：已采纳（1.3.0，2026-10-24）
- 相关：ADR-019、ADR-020、ADR-023；shared/src/group/discussion.ts、meetings.ts；design/refs-v1.3/ B4、M1–M3

## 背景
多 Agent 讨论的已知问题：互相附和（M2：相同角色降低效果）、辩论不稳定优于自洽（M3）、发言冗长、信息增量少（B4）。需要一个可检验、可截停、能出决议的协议。

## 决定
1. 七个常设会议室（可改名、增删）：战略室、评审室、作战室（限时 15 分钟、3 轮、CEO 主持）、红蓝对抗室（法务合规部压轴当蓝军）、赛马评审室、复盘室（复盘四步）、头脑风暴室（不批评）。能力：预约与例会（App 打开时到期执行）、会前文档、白板、主持、纪要（集团〔年份〕NNN号）、董事长旁听介入（插话最高优先 / 改议题 / 叫停 / 直接裁决）、回放。
2. 六步协议：
   1. 独立陈述：并行生成，**互不可见**（M1 的独立作答）；
   2. 质询：每方至少被质询一次，覆盖率必须 100%，蓝军质询所有人；
   3. 逐条回应：认账或反驳，不得回避；
   4. 秘书综合：共识 / 分歧 / 待验证；
   5. 决议：主持人（主模型）给出决议与待办；
   6. 纪要：编号、参会、要点、决议、待办（owner + 截止）。
3. 防空转：单条 ≤300 字；重复发言拦截；分歧为零或连续一轮无新论据提前结束；轮次与预算上限。
4. 表达规范打分（字节“文档清晰简单、不堆砌、不包装、坦诚清晰”）：结论先行、有来源、无套话；低于阈值的发言要求重写一次，取得分高的版本。
5. 决议经硬边界检查（ADR-023）：涉及自动发布 / 自动互动 / 多账号 / 刷量等动作的决议被拒；“对外发布由董事长本人完成”这类否定修饰紧邻动作时不误报。

## 取舍
- 讨论用省钱档模型、综合与决议用主模型：MiMo 实测三方三轮 34 条发言 ¥0.141。
- 不追求“辩论一定更好”（M3）：协议的价值在于可审计（谁说了什么、谁质询了谁）与能收敛到可执行的决议，而不是保证更正确。

## 后果
- MiMo 实测（evals/real/mimo-v1.3.json）：独立陈述互不可见、质询覆盖 100%、最长 300 字、决议未触碰硬边界；阅读 trace 后修正了综合解析对“来源：sp25、sp30”的误拆分。
