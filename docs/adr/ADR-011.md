# ADR-011 Key 加密后端可插拔；安卓用 AndroidKeyStore 硬件主密钥

- 状态：已采纳（0.10.0，2026-10-23）；取代 ADR-004 中“安卓与网页同一 WebCrypto 实现”的部分

## 背景
0.9.0 的 Key 用 WebCrypto AES-GCM 加密，加密密钥是不可导出的 CryptoKey，存在 IndexedDB（deviations-v9 D-KEYSTORE）。root 设备或被篡改的 WebView 理论上能在页面内调用解密。

## 决定
1. `web/src/local/secretBackend.ts` 定义 `SecretBackend`（available / encrypt / decrypt / info），三种实现：`webcrypto`（网页版与兜底）、`android-keystore`（自写 Capacitor 插件 SecureKeys）、`electron-safeStorage`（桌面系统钥匙串；Linux 只有 basic_text 时视为不可用）。
2. SecureKeys：AES-256-GCM 主密钥生成在 AndroidKeyStore（StrongBox 可用时优先，失败退回 TEE），可选“需解锁后 300 秒内可用”；WebView 只拿到 iv + 密文 / 明文，拿不到密钥。`decrypt` 永不新建密钥：密钥不在（卸载重装、换机、恢复别的设备的数据）返回 NO_KEY，界面提示重新填写。
3. 每条密文记录自己的后端（`Sealed.b`），解密按条分派。首次在 App 里用到 Key 时一次性迁移旧 WebCrypto 密文（模型 Key + 数据源凭证）：全部解开 → 新后端加密 → 逐条回读校验 → 一次写回 → 删除旧 WebCrypto 密钥。任何一步失败：什么都不写，继续用 WebCrypto，诊断页与“账号与 Key”写明原因，可“重试迁移”。
4. 诊断页（我的 → 运行状态 → 诊断）显示当前后端、`KeyInfo.isInsideSecureHardware()`、安全级别（Android 12+ `getSecurityLevel`）、StrongBox、是否需解锁、迁移状态。

## 后果
安卓上密钥不出安全硬件；代价：Key 与设备绑定，重装 / 换机后必须重填（这是预期，备份本来就不含 Key）。真机行为（硬件级别、StrongBox、重装）只能真机验证，见 design/acceptance-v10.md K7–K9。

## 何时重审
需要跨设备同步 Key，或要求每次使用都生物识别时。
