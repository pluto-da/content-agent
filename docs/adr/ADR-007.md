# ADR-007 文案集中：核心层按 id，界面层以中文原文为键

- 状态：已采纳（0.9.0，2026-10-23）

## 背景
0.9 新增大量错误白话与按钮；以后要多语言。

## 决定
shared/core/i18n.ts 按消息 id 存核心白话（错误、Agent 固定句），web/src/i18n.ts 继续以中文原文为键提供英文；新页面全部经 useT()。缺失回退中文，不显示 id。

## 后果
不用一次性重写 0.8 文案。代价：两套机制并存。

## 何时重审
正式支持第二语言（1.x）时统一为 id 制。

## 重审（1.0，2026-10-23）——统一为 id 制
- **决定**：界面文案改为 id 制。`web/src/locales/zh.ts`（源语言）与 `en.ts` 是唯一来源，id 形如 `ui.save_changes`，由英文意思生成、稳定，不随中文措辞变化。组件写 `t('ui.…')`（useT）或 `tr('ui.…')`（非 hook，JSX 属性 / 读屏标签用）。核心层 `shared/core/i18n.ts` 原本就是 id 制，本次补齐英文。
- **兼容**：数据表里的动态文案（能力名、导航描述、分段标签、平台名）仍以中文传入 t()，按中文反查 id 再取译文；查不到时原样显示并在英文界面下记入运行时漏翻（`window.__caI18nMiss`），截图 / 扫描脚本据此补齐。
- **迁移**：一次性代码改写（890 处 t('中文') → t('ui.…')，105 处写死的 JSX 文本、50 处 aria-label / title / placeholder → tr('ui.…')），共 1269 个 id，原英文表 516 条全部保留，新增 753 条英文。
- **校验**：`scripts/i18n-audit.mjs --strict`（英文缺失、未知 id、t() 里直接写中文、TSX 写死中文、核心英文缺失都必须为 0）；web `v1/i18n.test.tsx`、shared `v1.test.ts`；`scripts/a11y-scan.mjs` 在英文界面逐页收集漏翻（27 页 × 3 视口：0）。
- **仍未覆盖（如实）**：Agent 运行时生成的回复与工具卡片里由代码拼接的中文句子（如“已在主区打开 X”、确认卡里的金额句）、演示 / 示例数据、平台名在中文界面以外的写法；审计脚本只报告这些行数（约 700 行代码含中文，多为注释外的数据与运行时文案），不计入“缺失”。Agent 回复语言由模型与系统文件决定，不在 UI 文案表范围内。
- **后果**：两套机制合并为一套（UI 与核心都按 id）；新增文案必须同时写 zh 与 en，否则 CI 的 i18n 审计失败。
