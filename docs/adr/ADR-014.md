# ADR-014 进化分级自动生效：低风险自动采纳、核心规则仍须确认

- 状态：已采纳（1.0 第一部分，2026-10-23，用户决定）
- 相关：ADR-005（v9 运行时）、ADR-006（特性开关）、ADR-007（文案）；shared/src/evolution/index.ts、shared/src/agent/policy.ts

## 背景
0.9–0.11 里任何记忆、技能、lesson 的改动都要弹改动对比让用户逐条确认。日常使用中这类改动频繁、风险低、可回滚，确认卡成了噪音；而 SOUL / AGENTS / 硬边界 / 花钱策略这类核心规则一旦被改坏，影响全局，必须保留人工把关。

## 决定
1. **分级**（`evolutionRisk(target)`，代码判定，系统文件改不了）：
   - 低风险：`memory/preferences.md`、`memory/{lessons,people,topics,daily}/…`（记忆条目与 lesson）、`skills/<name>/…`（技能新增与修订）。
   - 高风险：根系统文件 SOUL / AGENTS / SYSTEM / IDENTITY / USER / MEMORY / TOOLS / APPROVAL / BOUNDARIES / HEARTBEAT / PROACTIVE_PREFERENCES / REVENUE / EVOLUTION，`config/`（含花钱阈值 limits.json、加载顺序），`semiotics/`、`docs/`，以及任何未列出的路径（默认高风险）。
2. **自动采纳**（`autoApplyProposal`）：低风险 + 开关 `evolution.autoLowRisk` 打开（默认开）时，先过现有校验——`validateProposal`（BOUNDARIES.md 拒收、放宽硬边界字样拒收、30 天冷却）、VFS 写入时的密钥拦截、大小上限与命名规则——全部通过才写入；任何一项不过就拒绝、不写入，并记审计 `denied`。
3. **免确认的范围只有两项**：`memory_write`、`system_file`（仅当目标低风险）。视频、删除、花钱（含超预算）、单价未知媒体等确认不受影响。
4. **可见与可撤销**：每次自动采纳都写审计（`system_file_change` / `memory_change`，带提案 id、风险级别、auto 标记）、EVOLUTION.md 最近变更记“自动采纳（低风险）”、成长记录列表显示“自动采纳 / 低风险”标签，提供一键回滚。回滚对追加型改动（如记忆条目）只撤掉新增的那几行，不覆盖之后的改动；记忆回滚同时删除对应的记忆记录。
5. **高风险不变**：仍生成改动对比卡，用户确认后由运行时写入；开关关闭时低风险也回到逐条确认。
6. 默认系统文件（AGENTS / SYSTEM / APPROVAL / BOUNDARIES 第 14 条 / EVOLUTION / MEMORY / TOOLS）同步改写为分级说法，见 design/proposals-v1.0.md。

## 后果
- 好处：日常经验沉淀不再打断对话；核心规则仍有人工把关；所有自动改动都有审计、可回滚。
- 代价 / 风险：自动采纳的技能版本可能质量不佳——用 lesson 门槛、validateProposal 与“一键回滚”兜底；技能新版本自动标 `status: testing`，验证不过按 EVOLUTION.md 降级。
- 已安装用户的设定文件不会被自动改写（首启默认只在新库生效）；他们可以在“Agent 设定”里恢复默认或按 proposals-v1.0.md 采纳。

## 测试
shared/test/v1.test.ts「进化分级自动生效」9 项（分级、开关默认开、自动采纳技能修订与新增技能、核心文件仍 pending、开关关闭、硬边界 / BOUNDARIES / 密钥被拒、回滚含追加型记忆、运行时记忆与技能免确认而 SOUL 仍确认）；web/src/v1/evolution.test.tsx 4 项（本机接线、审计、成长记录标签与回滚、开关关闭）。

## 何时重审
出现自动采纳的技能导致质量回退的实例、或用户要求把 lesson 以外的文件纳入低风险时。
