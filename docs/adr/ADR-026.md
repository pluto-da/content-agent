# ADR-026 信息披露与一致性：每个数字可追溯，与记账重算不一致就阻止生成；这不是对外信息披露

- 状态：已采纳（1.4.0，2026-10-24）
- 相关：shared/src/listed/disclosure.ts（REPORT_CHAPTERS / computeFigures / buildReport / checkConsistency / finalizeReport / traceFigure / renderReportHtml / buildDocx / questionBasis）、gov.ts（LISTED_HONESTY / PEN_NAME / scrubPrivate / privacyLeaks）；design/refs-v1.4 L4

## 背景
季报、年报和发布会的价值在于“数字可信”。模型写报告最大的风险是数字编造或与账不符；真实上市公司的披露义务又与本 App 无关，必须写清楚边界。

## 决定
1. 季报 / 年报固定 11 章：致董事长的信、经营概况、核心指标、各事业部经营情况、花费与预算执行、爆款与失败案例复盘、内控评价与内审发现、风险提示、组织与人才、下期展望、独立董事意见。
2. 数字一律是 Figure（值 + 单位 + 出处 kind:id），由 `computeFigures` 从记账、用量日志、收入账重算；没有数据写“无数据”，不估算。界面上每个数字可点开追溯到原始记录。
3. `checkConsistency` 在定稿前执行：缺数、数值不符、无出处、多出无法追溯的数字、花费账与用量日志不一致、损益不平（收入 − 总花费 ≠ 贡献利润，MiMo 实测后补充）、正文含隐私——任何一项都阻止生成并列出差异。“更正数字”只改报告不改记账，改完重新校验。
4. 导出：打印版 HTML（PDF）与 docx；封面用集团名与笔名，不含生日等隐私；每页页脚写诚实声明（LISTED_HONESTY）。封面为纯色着色（0.11 起不引入渐变，1.4 回归发现后修正）。
5. 董事长简报（日 / 周）：三件好事、风险、待你拍板，同样只用有出处的数字。
6. 业绩发布会：CEO 讲解文字稿，分析师（省钱档、另一模型）提问，每个问题先按名称、再按完整数字匹配报告依据；CEO 不确定时答“需核实，记入待办”并生成待办，禁止说报告外的原因或来源；单场预算 ¥0.5。

## 取舍
- 报告以生成时的单一语言为正式版本，避免中英两份数字不一致（英文界面显示中文正文，deviations V14-06）。
- 宁可阻止生成也不“自动修正”数字：自动修正会掩盖记账错误。

## 后果
- 机制测试：报告数字与记账一致否则阻止；报告不含 Key 和隐私（accept-v1.4 G10–G13、G21）。walkthrough 第 5 步：人为改错一个数字，生成被阻止。
