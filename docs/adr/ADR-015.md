# ADR-015 子 Agent 体系：监督者 + 子 Agent 作为工具，三层权力逐级收窄

- 状态：已采纳（1.2.0，2026-10-24）
- 相关：ADR-005（v9 运行时）、ADR-014；shared/src/super/agents.ts、shared/src/super/governance.ts

## 背景
1.1 只有一个 Agent；“子任务”是一次性、深度 1 的内部子运行。用户要求“超级 Agent 管控所有，还能再创建子 Agent”。
## 决定
1. 采用监督者范式（Claude Agent SDK subagents / OpenAI Agents SDK agents-as-tools 的共同做法）：超级 Agent（id `super`）是唯一监督者，子 Agent 作为它可调用的“专职执行者”，不做 handoff 式的控制权转移——结果总是回到超级 Agent 验收。
2. 定义即文件：`agents/<id>/AGENT.md`（front matter：id、name、description≤500、icon、version、permissions⊆L0–L2、tools 白名单、skills、model、budget、memory shared|private、schedule、platforms、dataSources、createdBy）。旧的平铺 `agents/*.md` 只是角色说明，不是子 Agent。
3. 层级：用户 0 → 超级 1 → 子 Agent 2 → 一次性子任务 3；子 Agent 不能把任务交给常驻子 Agent。并发默认 3（1–5）。
4. 交接契约：输入 `{goal, context_refs[], constraints, budget, deadline, output_schema}`，输出 `{summary≤300, artifacts[], cost, evidence[], open_questions[], failures[]}`，Schema 校验；不合格退回一次，仍不合格交给用户。
5. 创建：模板（8 个）/ 一句话起草 / `.agent.zip` 导入，三者都要用户确认（L3）；导入时 Key 扫描并把权限收窄到父级子集。
6. 子 Agent 的职责与权限改动属 L3；技能 / 记忆 / lesson 按 ADR-014 自动采纳。闲置 30 天只提示，不自动删除。
## 后果
- 子 Agent 是工具分工，不是多账号；没有任何登录态。
- 编排逻辑全部在 shared（纯函数 + 注入执行器），App 与真实 MiMo 实测走同一套 Orchestrator。
