# ADR-020 临时会话：能派单不拉群、能拉群不开会；@ 集结、√ 解散，有上限、不提权

- 状态：已采纳（1.3.0，2026-10-24）
- 相关：ADR-019；shared/src/group/sessions.ts；design/refs-v1.3/ X5（王川“用 @ 集结，用 √ 解散”）

## 背景
部门之间需要即时对齐，但“开会”成本高且容易空转（refs-v1.3 B4）。多 Agent 自由聊天又会无限消耗 token、重复发言。

## 决定
1. 数据结构 `TempSession{id, topic, goal, initiator, members, context_refs, budget, ttl, max_turns, status, outcome}`。
2. 6 种自动触发：OKR / KR 冲突（数据中心检出方向相反或争用独占资源）、跨部门工单、否决后协商、预算超权、指标异常、董事长“拉个群 / 叫上 X 和 Y”。成员按议题自动推荐 ≤5 个。
3. 上限：10 条消息、¥0.2、30 分钟（可调）；同时存活 ≤5，超出排队。到任一上限自动小结并解散。
4. 发言规则：每条须有论点或证据；与已有消息高度重复的被拦截；疑似 Key 拒收；数据须写来源，没有写“推测”。
5. √ 解散只能由发起方或董事长执行；解散前必须出小结：结论、待办（转工单，含 owner 与截止）、未决（升级给 CEO 或转会议室）。会话可“升级为会议”，带走上下文。
6. 会话不赋予任何新权限：成员在会话里提出的动作仍按各自权限与 DOA 判定；会话里的“同意”不是授权。

## 取舍
- 不做常驻群：会话只为一个目标存在，目标达成即解散，避免“群越来越多”。
- 阈值偏保守（10 条 / ¥0.2）：MiMo 实测 4 条即达成一致、花费 ¥0.00122（evals/real/mimo-v1.3.json）。

## 后果
- 机制测试覆盖：重复发言被拦截、TTL 与上限解散、会话不提升权限（accept-v1.3 F6、F17）。
