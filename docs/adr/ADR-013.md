# ADR-013 安卓传输与提醒：JS 构造 multipart 兜底；系统闹钟预排提醒

- 状态：已采纳（0.10.0，2026-10-23）；补充 ADR-009

## 决定
- 传输（`web/src/v9/transport.ts`）：安卓 App 默认用 JS 手工拼 multipart 字节（RFC 7578），网页 / 电脑用 FormData；FormData 抛错时自动换 JS 构造重试一次。二进制响应若被原生层当成 Base64 文本返回，按声明类型识别并解码；空文件、跨域、上传 / 下载失败都给白话原因。每次 multipart / 二进制请求记一条 trace（字段名、类型、字节数、返回 Base64 长度、耗时；不记头部和内容），诊断页可看、导出，并有用户点击才运行的 httpbin 回显自检。
- 提醒（`web/src/v9/reminders.ts`）：安卓用 @capacitor/local-notifications 预排（`schedule.at` + `allowWhileIdle`），App 关闭也由系统弹出；Android 13+ 申请 POST_NOTIFICATIONS，Android 12+ 检查 SCHEDULE_EXACT_ALARM（未开时如实提示可能延迟，并给“去系统设置开启”）；拒绝权限不预排、不崩，到点在 App 内顶部提示；系统已弹过的那次 App 打开后不重复弹；重复提醒到点排下一次。只发通知，不执行任何动作。

## 后果
真机行为（CapacitorHttp 实际表现、Doze 下的准点、厂商省电策略）只能真机验证，见 acceptance-v10 T2、N2、N3。
