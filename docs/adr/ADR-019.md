# ADR-019 融合组织：总部职能部门 + 事业部 + 薄共享能力中心 + 专业委员会，清单即组织、默认关闭

- 状态：已采纳（1.3.0，2026-10-24）
- 相关：ADR-015（子 Agent 体系）、ADR-016（权限分级）；shared/src/group/org.ts、web/src/v13/；design/refs-v1.3/（X1–X5、A1–A4、T3、B5）

## 背景
1.2 已有“超级 Agent 管子 Agent”。子 Agent 增多后需要分工、制衡与可解释的协作结构。PROMPT-v1.3 要求吸收小米（职能部门 + 委员会 + 经管会 + @ 集结 / √ 解散）、阿里（薄中台 + 政委 + 复盘）、腾讯（事业群 + 赛马 + 灰度）、字节（Context not Control + OKR 公开 + 文档先行）可迁移的机制，同时避免“大企业病”（refs-v1.3 R1）。

## 决定
1. 角色：董事长 = 你；CEO = 超级 Agent；部门负责人与执行 Agent 都是 1.2 的子 Agent，**不新增权限来源**，子级权限永远是父级子集。
2. 默认组织：4 个总部职能部门（参谋部、组织部、财务部、法务合规部）+ 4 个事业部（短视频、图文、电商、国际）+ 共享能力中心（数据中心、素材中心、技能与模板库、用户运营）+ 5 个委员会（经营管理委员会、人力资源委员会、质量委员会、技术委员会（设计委员会隶属其下、不单独计数）、采购委员会）。可增、删、改名、合并；结构变化为 L3。
3. 清单即组织：`company/departments/<id>/DEPT.md`、`company/committees/<id>/COMMITTEE.md`，front matter 写职责、负责人、成员、编制（单部门 ≤20、同时运行 ≤3）、预算；随 VFS 备份导出，可 diff、可回滚。
4. 集团模式默认关闭（`config/group.json`），启用时才写 `company/`；退回时 `company/` 进回收站、原 1.2 数据不动。
5. 每个机制都可开关、可度量、可淘汰（制度库“机制开关”，驾驶舱给出开会花费占比、上下文命中率、赛马效果）。
6. 界面统一叫“统领”，文案注明“虚拟组织、不是法律实体；对外发布由你本人完成”“参照公开报道，非任何公司官方制度”。

## 取舍
- 不照搬任何一家：小米给骨架（职能部门 + 委员会），阿里给“薄中台”（共享中心只复用、不审批），腾讯给事业部 + 赛马，字节给上下文流与表达规范。
- 不做“多账号 / 团队”：集团内全是本机 Agent，同一个你。
- 代价：概念变多。缓解：默认关闭、7 个子页即全部入口，“我的”仍 ≤12 项。

## 后果
- 1.2 子 Agent 启用集团模式时按职责自动归入默认部门（migrateV13）；无法判断的进“待分配”。
- 8 个历史版本备份恢复 → 迁移 → 启用 → 开会 → 降级全部通过（accept-v1.3 F19）。
