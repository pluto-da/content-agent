# ADR-023 DOA 引擎：决策权限表直接执行；越权拦截并审计，超权生成请示；硬边界任何人不可放宽

- 状态：已采纳（1.3.0，2026-10-24）
- 相关：ADR-016（L0–L3 + 禁止级）、ADR-019；shared/src/group/doa.ts（parseDoa / doaCheck / checkResolution）、regulations.ts、company/regulations/02-doa.md；design/proposals-v1.3.md P2

## 背景
10 项制度如果只是文字，Agent 会“读了不照做”。权责必须由代码执行，并与 1.2 的权限分级叠加而不是替代。

## 决定
1. `company/regulations/02-doa.md` 的 front matter 是唯一来源：五类控制事项（花钱、对外、改规则、改权限、硬边界）× 决定者（部门负责人 / 委员会 / CEO / 董事长 / 禁止），其余为日常事项。
2. 默认阈值（proposals-v1.3 P2，随新安装提供，已安装用户在 App 内确认）：单次花钱 ≤ ¥0.5 部门负责人、≤ ¥2 CEO、以上董事长；对外只能董事长；改权限须人资委审议后董事长批准；硬边界 = 禁止。
3. 执行顺序：1.2 权限分级（调用者授权 ∩ 工具级别）→ DOA → 硬边界。任何一层拒绝即拒绝；越权写审计；“超权但合规”的事项自动生成请示进收件箱。
4. 否决权仅法务合规部与质量委员会，且必须引用有效条款（条款引用校验）；申诉一次由 CEO 裁决；硬边界否决不可申诉，董事长也不能推翻。
5. 会议 / 会话决议同样过 `checkResolution`：命中自动发布、自动互动、多账号、刷量、抓私有数据、部署 154.8.183.93、写入真实密钥等动作即拒；否定修饰须紧邻动作才算豁免（MiMo 实测第一次的误报已修）。
6. 制度修改走 L3（提案 → 委员会审议 → 董事长批准），带版本、可回滚；章程与 DOA 的默认值改动只写 proposals。

## 取舍
- 不让模型自行解释权限：DOA 是数据，不是提示词。
- 代价：阈值固定在文件里，个性化要走 L3。

## 后果
- 机制测试：DOA 越权被拒、否决须引用条款、会话 / 会议不提升权限、硬边界决议被拒（accept-v1.3 F4、F11、F17）。
