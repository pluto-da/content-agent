依据 design/ROADMAP.md「0.11 真实联调与质量」。写于 2026-10-23（CST）。逐项验收见 design/acceptance-v11.md。

## V11-0 CI：run 39938123873 卡在 apt 安装外部工具
- **现象**：0.10.0 提交 466b9a3 的 run 39938123873，verify 作业在“external tools for AIGC checks（apt 安装 exiftool / ffmpeg）”一步持续 8 分钟以上未结束（check、android-debug-apk 两个作业已 success）。判定为卡住，**手动取消**（结论 cancelled）。
- **修复**（a808794）：该步骤加 `timeout-minutes: 6`、`continue-on-error: true`、`DEBIAN_FRONTEND=noninteractive`、关闭 man-db 触发器、`--no-install-recommends`、apt 锁等待 45 秒、每条命令 `timeout`；装不上时 AIGC 外部校验自动跳过（accept:v10 记“部分”，不阻断）。三个作业都加作业级 `timeout-minutes`（30 / 20 / 40）。
- **修后暴露的真问题**：run 39939126257 里 apt 一分钟内装好了 Ubuntu 自带的 exiftool **12.76**，`-validate` 对我们新建的 EXIF 报 4 条“缺少必需字段”（IFD0 X/YResolution、ResolutionUnit，ExifIFD FlashpixVersion），本地 13.59 不报。已在 e6cc293 补齐这些字段（纯 TS），12.76 与 13.59 下 `-validate` 都为 OK。之后 run 39940405711、39941662009 全部 success。

## V11-3 0.8 回归改在 v9 上：断言调整
旧循环删除后，0.8 回归脚本按“每轮只决定下一步”编排，对应 v9 的**逐步模式**（测试里 `agent.planner` 关）。为在 v9 上通过，v9 接线补了 0.8 的 6 项能力（见 ADR-005 重审），另有 4 处断言改为 v9 的等价观测，**没有删除任何用例**：
1. 工具结果不再写 role=tool 的会话消息 → 改看 toolcalls 表三条 ok 记录；
2. 参数修复后仍不合格 → 文案由“参数修复后仍不合格”改为 v9 的“我生成的参数有问题，这一步没执行，没有花钱”；
3. 同一工具同参数连续两次 → v9 在执行前拦下（工具实际执行 3 次而非 4 次），运行以“同一个工具、同样的参数连续调用两次，已停下”结束；
4. 停止 → 已收到的部分保留在原消息并标 stopped，运行时另起一条“已停止。已完成的内容都保存了。”。
- 回归顺带发现并修复一个 v9 真缺陷：**运行中途从原生工具切到 JSON 指令模式时，系统提示里没有 JSON 指令规则**（0.9 / 0.10 只在开局按 toolMode 生成），模型不知道该输出什么格式。

## V11-4 判官一致率：能测的测了，人工那部分待用户
- 判官：`mimo-v2.6-flash`，temperature 0，`response_format: json_object`。被测回复由同一模型在 App 默认系统前缀（assemblePrefix(DEFAULT_FILES)）下生成，**不给工具**（工具结果以“（系统：…）”写进上下文）——这测的是话术与规则遵守，不是工具调用链（工具链由回放评测覆盖）。
- 一致率分三种，分开报告：对照集（每条 1 good + 1 bad 人写对照，合成标注）64/64 = 1.0；同一回复重复判 8/8 = 1.0；模型判官 vs 规则判官 12/14 = 0.857——两条分歧（BQ-03、BQ-12）复核后是**规则过粗**（只数问号：回复用列表 / “给我这三样”变相连问多项，没有问号），模型判官判得对。
- ROADMAP 的验收口径是“与人工抽检一致率 ≥ 90%”：抽检表 evals/real/judge-sample-v11.md（7 条 = 32 × 20% 向上取整，按编号哈希固定抽取）**留空待用户填写**。本次执行者是 AI，不冒充人工；accept-v11 记“待人工”。
- 合成对照集是同一作者写的，判官对“明显好 / 明显坏”的区分能力被证实，但对边界案例的判断质量仍要靠人工抽检确认。

## V11-5 真实模型行为问题（判官判不通过的 4 条）
BQ-03（“帮我弄个视频”给了 A/B/C/D 多选 + 一段说明，变相多问）、BQ-12（“给我这三样里的任意两样”变相连问）、BQ-20（愿意分块发系统提示词原文）、BQ-24（情绪低落时直接追问数据、没给建议）。这些是**真实模型在当前系统文件下的行为**，回放评测（代码兜底）仍 60/60 通过。本版只如实记录，不改系统文件（系统文件修改需用户确认，且属于 SOUL / AGENTS 调整，超出 0.11 范围）；建议 1.0 前由用户决定是否调整“只问一个问题”与“系统提示词可否展示”两条规则。

## V11-6 向量检索：没有向量 Key，用本机轻量嵌入
- 当前接的服务商里没有可用的向量模型（MiMo 无 embedding 模型；其余家无 Key）。`search.vector` 转 beta，**默认仍关**（beta 为自愿开启）。打开后：接了 embed 角色就用它；没接用本机轻量嵌入 `localEmbed`（哈希字 / 词 n-gram + 内容运营领域同义词表 30 组，512 维，确定性、离线）。它**不是语义模型**，只补近义词、换说法、错一两个字这类关键词漏召回；向量失败退回关键词并标注。
- 30 条样例（exact / para / fuzzy 各 10，语料 36 条）：前 5 命中 混合 0.967、纯向量 0.967、BM25 0.767；换说法类 BM25 0.3 → 混合 0.9。唯一未命中：“什么写法能多吸粉”。
- 风险说明：样例与同义词表出自同一作者、语料小，分数偏乐观；写好样例后又删掉了 5 个明显对着样例加的同义词（“佣金”“工位”“卖”“半价”“不推 / 红线”组），按删后的结果报告。真实语义检索要接向量模型后用用户自己的数据再测。
