## 三、待你确认的修订建议（未写入）

### P-1 编号列表 / “一句话说明 A、B、C”也算连问（BQ-03、BQ-12）

- 文件：AGENTS.md「提问」一节（高风险，须确认）。
- 改动对比：

```diff
 - 不变相连问：不列 A / B / C / D 让大哥逐项回答，不说“给我这三样 / 任意两样”这类一次要多项信息的话；缺好几样时先做假设推进，只问最关键的那一个。
+- 判断标准：大哥看完回复，需要回答的“空”只有一个。编号列表里每一项都要他填、或“一句话说明卖什么、给谁看、发哪个平台”这种一句里要三项，都算连问。
+- 缺好几样时：先按最常见的情况假设（写出假设），把最关键的一项做成问题，其余放进“我先按 xx 来，不对再改”。
+  例：“帮我弄个视频”→“先确认一件事：发抖音还是小红书？我先按 30 秒口播、AI 配音来准备，不对再改。”
```

- 依据：evals/real/judge-v1.json 的 BQ-03 / BQ-12 回复；0.11 与 1.0 两次真实调用均不通过。
- 风险：问得更少，假设可能错——用“写出假设、不对再改”兜底；不涉及花钱与硬边界。
- 回滚：「Agent 设定 → AGENTS.md → 历史版本」恢复上一版。

### P-2 不输出占位 / 中断标记（BQ-10）

- 文件：SYSTEM.md（高风险）。
- 改动对比：

```diff
+- 回复必须是给大哥看的完整句子；不输出“[已取消]”“[空]”“…”之类占位或中断标记。不知道结果时直接说“我这边看不到是否已发布”。
```

- 依据：BQ-10 生成端只输出“[已取消]”。属偶发，先观察：建议 1.x 若再出现两次再采纳。
- 风险：几乎没有。回滚同上。

### P-3 没有工具时不要把工具调用写成文本（BQ-23）

- 说明：这是评测设置（不给工具）引起的，App 里有工具。建议**不改系统文件**，改评测：evals/judge.ts 的评测说明加一句“本轮没有可用工具，需要工具时用文字说明你会做什么”。这是代码 / 评测改动，不是系统文件，下次复测时一并做（不改 rubric，只改生成端说明）。
