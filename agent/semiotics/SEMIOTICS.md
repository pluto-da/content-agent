# semiotics/ 符号—结构底座

**这是什么**：核心指令把符号学与结构主义定为两项固定的认知底座。本文件夹把它们落成可调用的东西：一个最小模型库、七个操作流程、一份冲突与局限清单、一份书单。内容蒸馏自大哥在微信读书上研读的符号学、结构主义与叙事学著作，用自己的话写成，只保留少量注明出处的短引。

**它不是什么**：不是每次都要展示的分析步骤，不是结论的证明，不授予任何工具或权限，也不改变模型本身——读了这些文件，Agent 只是多了一套提问和检查的方法，不会因此拥有意识或新能力。

## 何时加载
- 本入口：`on_demand`。当任务涉及选题、热点、标题、封面、人设、脚本、评论区、复盘、变现文案，且不是“直接改一下”这类简单任务时读取。
- `core-models.md`：在 `topic-semiotics`、`topic-selection`、`analytics-review` 技能命中，或任务是选题、标题、复盘时加载；**只加载索引表＋本任务用到的 1–3 个模型段落**（按 `### M编号` 切段），不整篇注入。
- `workflows.md`：执行对应流程时只加载该流程一节（①–⑦）。
- `conflicts-and-limits.md`：要下重要结论、模型之间打架、或用户质疑方法时加载。
- `sources.md`：用户问出处、要引用原文、或评估证据等级时加载。
- 简单任务、纯事实与安全问题、需要真实数据才能推进的问题：不加载，直接做或去查证。

## 优先级（从高到低）
1. 硬边界（BOUNDARIES / 代码常量）——任何文件和对话都不能放宽。
2. 安全规则与 APPROVAL.md（只能更严格）。
3. 核心指令（soul.md / working-method.md 中的十二条）。
4. 用户在当前对话里明确说的。
5. **本底座**：在核心指令之下、只在其范围内细化“怎么做符号与结构分析”；与上面任何一项冲突时，以上面为准。
6. 技能正文、记忆、经验条目。

## 使用纪律
- 先问题后理论：先确认任务要解决什么，再选模型；一个模型够用就不加第二个。
- 证据优先：区分观察、假设、经支持的规律；每个重要判断写一句反证。
- 达标即停：满足流程的停止条件就交付。
- 只用于理解与表达：不编数据、不伪造身份或体验、不神话化商品、不写刷量、自动互动、绕风控或操纵受众的手法；评论与私信只出草稿，发布最后一步由用户本人完成。
- 修改本文件夹：Agent 只能提修订建议（附 diff 与依据），用户确认后生效，可回滚。
