## 目标
少重算、少空等、少返工，输出一次合规。应用层碰不到 GPU，但“调用编排层”可以 1:1 平移这套目标。

## 十条原则（推理层 → 本 Agent 的做法）
1. **分阶段配资源**：采集、聚类、打分用便宜快模型；成稿用强模型；审核用中档模型加规则。
2. **稳定前缀**：提示词固定顺序 硬边界 → soul → 规则 → skill → 平台规范，逐字节不变；素材、时间、用户输入放最后。同一素材改写多个平台时共享前缀，顺序发出以便后一次命中缓存。
3. **草稿-验证分档**：便宜模型出稿，按置信度决定验多少。高置信直接进待审；中置信只复核标题与合规命中；低置信才让强模型整篇重写。不要每篇都全量复核。
4. **复核力度跟着把握度变**：命中敏感词、超字数、事实性陈述多的稿件加重复核，其余从轻。
5. **有界重放**：流水线每步落库，失败只重跑失败那一步；用户改稿后的局部重写只发送选中段加前后有界窗口；多轮对话只保留最近窗口加摘要。
6. **编排与执行重叠**：文本、配图、配音可并行发出，按服务商限速设并发上限。
7. **可复现评测**：temperature=0，支持就传固定 seed；记录模型版本 + 提示词哈希 + 输入哈希；同一哈希直接复用结果；A/B 一次只改一个变量。
8. **生成时约束**：每个 skill 声明输出 JSON Schema（标题字数、标签、正文、平台字数上限）；能传 response_format 就传，否则本地校验 + 一次带错误信息的修复重试。
9. **健康路由**：按能力、成本、近期失败率、延迟选路；主路失败或失败率高时切备用；记录每家的成功率与 p95。
10. **统一编解码**：业务只认一种结果格式（含 reasoning、usage）；思考内容不进成稿和日志正文；按思考模式给 max_tokens 默认值（非思考 8192、思考 65536），请求前做上下文上限预检。

## 度量
单篇成本、缓存命中率（目标 > 50%）、一次通过率、返工放大系数（越接近 1 越好）、p50/p95 延迟、各服务商失败率。见“设置中心 → 运行状态”。

## 边界与误区
- 拿不到 logits，“置信度”只能用代理信号：合规规则命中数、Schema 是否一次通过、字数越界、两次采样是否一致。
- 不要为了“投机”引入两次全量生成；草稿模型必须明显更便宜（单价建议 ≤ 强模型的 1/5），否则得不偿失。
- 缓存命中依赖前缀逐字节一致：时间戳、随机示例、用户名都要挪到末尾。
- 确定性 ≠ 正确性：它只让评测可复现，不证明内容更好。
